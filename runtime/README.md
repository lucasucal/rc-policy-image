Spec: `docs/policy-runtime-pin.md`; contracts: `docs/runtime-interfaces.md` sections 2, 5.

| Path | What |
|---|---|

python -m pip install pytest huggingface_hub   # hub tests skip without it

The `-I` test needs `rc_sdk` and `rc_runtime` installed (`pip install ./starter/rc_sdk ./runtime`); it skips otherwise.

## Policy transport

The class server uses HTTP by default, including in the private
[Whistle mock setup](../docs/api.md#whistle-mock-deployment). The published
image also supports optional HTTPS via `RC_POLICY_TLS_CERT` and
`RC_POLICY_TLS_KEY`. Set both variables to enable it. A program entry point
runs its own server.

NATTEN 0.21.7 is installed from the separately hash-pinned Python-only sdist in
`locks/requirements.natten.txt`. Its `flex-fna` backend uses PyTorch and does not
include the compiled libnatten kernels. It has passed a FLUX 3 Action GPU probe;
see `docs/verification/natten-rc02-2026-11-27.md` for tested devices and limits.
A new release must be built, tested and pinned before this is available to teams.

## Update the locks

`./runtime/make-locks.sh` (needs `uv`). It resolves for `x86_64` and `aarch64` (manylinux_2_28, Python 3.12) and fails if the pinned versions differ between architectures. Commit the result. It also writes `locks/requirements.sdist.txt` (the one sdist-only pin, `antlr4-python3-runtime`, which the Dockerfile builds from the hash-checked sdist) and strips `docopt` and `embreex`. The wheels' existence is checked by the resolver; it says nothing about GB10 behavior.

## Layer order and slices (v8)

The Dockerfile installs the lock as four hashed layers, least to most frequently changing: `s1-cuda-torch` (`nvidia-*`, torch stack, triton), `s2-jax` (JAX, cupy, numba, llvmlite), `s3-biglibs` (onnxruntime, opencv, open3d, casadi, pyarrow, scipy, ...), `s4-rest` (everything else, the `*` catch-all). Membership is by package-name patterns in `locks/slices.txt`; `make-locks.sh` runs `tools/split_lock.py`, which copies each requirement block (hashes included) verbatim from the per-arch full lock, so the guarantee is unchanged (`pip --no-deps --require-hashes` per slice) and amd64/arm64 get the same slices. `tests/test_split_lock.py` proves the slices are up to date, have no duplicates and their union is the full lock. After editing `slices.txt` or a lock, re-run `make-locks.sh` (or `python3 runtime/tools/split_lock.py runtime/locks/requirements.<arch>.txt runtime/locks/slices.txt`) and commit. Then come the sdist pin, the numba nvvm links, the baked weights (before the code, so code-only releases do not rebuild them), and last rc_sdk/rc_runtime, `rc_release.py`, `release.json`.

## Size trims (v8)

Each runs in the same `RUN` as the install that created the files, via `tools/trim_site_packages.sh`:

| Trim | Why it is safe |
|---|---|
| `triton/backends/nvidia/lib/cupti` and `cupti-blackwell` (CUPTI `.so` copies and two 48 MB `libcupti_static.a`, about 207 MB unpacked) | Only referenced by `triton/knobs.py` (`cupti_lib_dir`) and `triton/profiler` (the proton profiler). Compilation and kernel launch use `ptxas`, `libdevice.10.bc`, `include/` and `driver.c`, all kept. The CUDA runtime's own CUPTI (`nvidia-cuda-cupti`) is untouched, so `torch.profiler` still works. Triton's profiler (`triton.profiler`) no longer works; nothing in the rules uses it |
| `pip install --no-compile` and a `__pycache__` sweep after the last slice | `PYTHONPYCACHEPREFIX=/scratch/pycache` makes Python ignore in-tree `.pyc`, so baked ones are never used |
| `/root/.cache`, `/tmp/pip-*` | pip leftovers (`PIP_NO_CACHE_DIR=1` already) |

Not done: stripping `.so` debug symbols, symlink de-duplication, removing `cicc`/`nvcc`, headers, `cuda-compat`, any package removal. Expected saving of the applied trims: roughly 50-60 MB compressed (about 280 MB unpacked); to be measured on the first v8 build.

## Build and publish

There are no organizer-provided base models (the curated base cache and `/hf-base` were removed in v11): a policy loads everything from its own snapshot at `/weights`.

1. Build each architecture on a host of that architecture (arm64 on a Spark) and push by digest:
   `docker buildx build --platform linux/arm64 -f runtime/Dockerfile --build-arg BASE_IMAGE=nvidia/cuda:13.0.3-base-ubuntu24.04@sha256:<pin> --build-arg RELEASE_ID=... --build-arg IMAGE_TAG=... --push .`
   then the same for `linux/amd64`, then `docker buildx imagetools create` for the manifest list. Pin the base by digest.
2. Per-architecture inventory, from each image (tools are kept in `/opt/rc/tools`):
   `docker run --rm --entrypoint python <img>@sha256:<platform digest> -I /opt/rc/tools/rc_release.py packages > packages.arm64.json` (same for amd64), and `... rc_release.py reserved > reserved.json`.
3. Write the published release (digests are only known after push):
   `python runtime/tools/rc_release.py write -o runtime/release.json --release-id ... --repository ... --tag ... --manifest-digest sha256:... --platform-digest linux/arm64=sha256:... --platform-digest linux/amd64=sha256:... --config-digest linux/arm64=sha256:... --config-digest linux/amd64=sha256:... --packages linux/arm64=packages.arm64.json --packages linux/amd64=packages.amd64.json --reserved reserved.json`
   Commit `runtime/release.json`.
   `/opt/rc/release.json` inside the image is the `--partial` build-time copy (no digests); the loader reads only `reserved_modules` and `stdlib_module_names` from it.
4. Update the numeric format and package status cells in `numeric_formats.json` / `--package-status` only from real test results.

## Build and publish via GitHub Actions

Free native builds (amd64 on `ubuntu-24.04`, arm64 on `ubuntu-24.04-arm`, no QEMU) run in the small public mirror `lucasucal/rc-policy-image`, which holds only the build context (`runtime/` image files, `starter/rc_sdk/`) and the workflow from `runtime/ci/build-image.yml`. The monorepo stays private and is the source of truth; never edit the mirror.

Release:

1. Commit the runtime/lock changes here. Then `git clone git@github.com:lucasucal/rc-policy-image.git ../rc-policy-image` (once) and `runtime/tools/sync_build_repo.sh ../rc-policy-image --tag v6`. It rsyncs exactly the context, installs the workflow and README, and commits with the monorepo SHA in the message (idempotent; it never pushes).
2. `cd ../rc-policy-image && git push origin main v6`. The tag push starts the workflow (or run it by hand with a `tag` input).
3. The workflow builds both architectures without layer cache (the pip layer is several GB and would not fit the 10 GB cache limit), pushes each by digest, creates `ghcr.io/lucasucal/rc-policy:v6` plus `:v6-amd64` / `:v6-arm64`, prints `imagetools inspect`, and uploads artifacts: `build-<arch>` (`digest-<arch>.txt`, `packages.<arch>.json`, `reserved.<arch>.json`) and `release-inputs` (digests, `manifest.json`). Use them for `rc_release.py write` (step 3 above) and commit `runtime/release.json`.
4. One-time: the package `rc-policy` must grant the mirror repo write access (package settings, Manage Actions access, Add repository, Write); this is done, and the workflow publishes to `ghcr.io/lucasucal/rc-policy`. Build args match the Spark builds (per-arch base digests, `RELEASE_ID=rc-policy-<tag>`, `IMAGE_TAG=<tag>`); the baked `release.json` is `--partial` as before.

### Release checklist (next: v11)

v11 removes the curated base cache. The Dockerfile no longer creates `/hf-base` and no longer sets `HF_HUB_CACHE=/hf-base` (KSI-029: downloads inside the image failed with `PermissionError` on the read-only `/hf-base`); `HF_HOME=/scratch/hf` stays, so the hub cache is `/scratch/hf/hub`, the only writable place, and training or export runs inside the image with `-e HF_HUB_OFFLINE=0` work without extra flags. The runner sets `HF_HUB_CACHE=/scratch/hf/hub` itself (so v10 behaves the same until cutover) and mounts only `/submission` and `/weights`. `tools/build_base_cache.py` is deleted and `rc_release.py write` has no `--base-cache`; the written `release.json` has no `base_cache` key, and the validator accepts only a legacy `"base_cache": null` (v10's committed file). The loader is unchanged apart from its network hint. Commands assume `T=v11`, `IMG=ghcr.io/lucasucal/rc-policy`.

1. Laptop: from the commit to release, `runtime/tools/sync_build_repo.sh ../rc-policy-image --tag $T`, review the mirror diff (expected: `runtime/Dockerfile`, `runtime/rc_runtime/loader.py`, `runtime/tools/rc_release.py`, and `runtime/tools/build_base_cache.py` deleted), then `git -C ../rc-policy-image push origin main $T`. Needs push access to `lucasucal/rc-policy-image`.
2. CI (mirror repo): wait for the `build-image` run. Then on the laptop:
   `RUN=$(gh run list -R lucasucal/rc-policy-image -b $T -L 1 --json databaseId -q '.[0].databaseId'); gh run download $RUN -R lucasucal/rc-policy-image -n build-arm64 -n build-amd64 -n release-inputs -D /tmp/rc-$T` (one subdirectory per artifact: `build-arm64/`, `build-amd64/`, `release-inputs/`). `A=/tmp/rc-$T`
3. Laptop: check the inventory before writing anything.
   `diff $A/build-arm64/reserved.arm64.json $A/build-amd64/reserved.amd64.json` (must be empty);
   `python3 -c "import json,sys; old=set(json.load(open('docs/verification/release.v10.json'))['reserved_modules']); new=set(json.load(open(sys.argv[1]))); print('removed', sorted(old-new), 'added', sorted(new-old))" $A/build-arm64/reserved.arm64.json`
   (expected: both empty, since the lock did not change; anything else needs an explanation).
   Manifest digest: `jq -r .digest $A/release-inputs/manifest.json` (equals the top-level `Digest:` of `docker buildx imagetools inspect $IMG:$T`); config digests: `docker buildx imagetools inspect --raw $IMG@<platform digest>` then the `config.digest` field.
4. Laptop: write and validate. Use Python 3.12: `write` copies `stdlib_module_names` from the interpreter it runs on.
   `python3.12 runtime/tools/rc_release.py write -o runtime/release.json --release-id rc-policy-$T --repository $IMG --tag $T --manifest-digest sha256:... --platform-digest linux/arm64=$(cat $A/build-arm64/digest-arm64.txt) --platform-digest linux/amd64=$(cat $A/build-amd64/digest-amd64.txt) --config-digest linux/arm64=sha256:... --config-digest linux/amd64=sha256:... --packages linux/arm64=$A/build-arm64/packages.arm64.json --packages linux/amd64=$A/build-amd64/packages.amd64.json --reserved $A/build-arm64/reserved.arm64.json --python-version 3.12.3 [--docs-url ...]`
   `python3 runtime/tools/rc_release.py validate runtime/release.json && cp runtime/release.json docs/verification/release.$T.json` (the new file has no `base_cache` key).
5. Laptop: `python -m pytest checks/rc_checks/tests runtime/tests backend/tests -q` (`test_committed_release_validates` checks the new `runtime/release.json`).
6. Spark (arm64, before cutover): pull by the manifest digest, confirm the platform digest, and check the environment and the missing mount point:
   `docker pull $IMG@<manifest digest> && docker image inspect $IMG@<arm64 platform digest> >/dev/null`
   `docker run --rm --entrypoint sh $IMG@<arm64 platform digest> -c 'env | grep ^HF_; test ! -e /hf-base && echo no-hf-base'` (must show `HF_HOME=/scratch/hf`, no `HF_HUB_CACHE`, and print `no-hf-base`)
   Download inside the image as a team training or exporting would (needs network; `--read-only` and a tmpfs `/scratch` as judged):
   `docker run --rm --read-only --user 10001 --tmpfs /scratch:exec --tmpfs /tmp -e HF_HUB_OFFLINE=0 --entrypoint python $IMG@<arm64 platform digest> -I -c "import os; os.makedirs('/scratch/hf', exist_ok=True); from huggingface_hub import hf_hub_download as d; print(d('openai-community/gpt2', 'config.json'))"` (must print a path under `/scratch/hf/hub`; v10 fails with `PermissionError` on `/hf-base`)
   Then rerun the v10 regression matrix (`docs/verification/v10-validation.md`) with the judged runner argv (only `/submission` and `/weights` mounted) and record it as `docs/verification/$T-validation.md`.
7. Commit `runtime/release.json` and `docs/verification/release.$T.json`. The deploy workflow rebuilds the backend image because `runtime/release.json` is in its path hash. Set `RC_POLICY_IMAGE=$IMG@<manifest digest>` on every Spark runner, remove any `RC_BASE_CACHE_DIR` from the runner env (it is ignored now) and delete `/srv/rc/hf-base` if present, then follow the cutover checklist in `contestants/ORGANIZERS.md`.

## Deviations from the research / contracts

- `huggingface_hub` is `>=1.32,<2` (locked 1.33.0), not 2.4.0: LeRobot 0.7.0 caps `diffusers<0.40`, and diffusers 0.38/0.39 require `huggingface-hub<2`.
- `rc_runtime --selfcheck` exit codes: `71` (new) for import/resolve failures; 70/72 as in the contract.

Removed in v9: v8 also deleted `tests/` directories inside numpy, scipy, pandas, sympy and scikit-learn.
`numpy.testing` imports `numpy._core.tests._natype`, so scipy, keras and LeRobot failed to import.
Package test directories are no longer trimmed, and the CI build now runs an import check before
tagging (see `ci/build-image.yml`).
